# Threshold Age of Lifespan Inequality in a Multistate (Healthy–Disabled) Framework

Reproducible code accompanying Upadhyaya & Kumar, *"Threshold Age of Lifespan
Inequality in a Multistate Framework."* This repository extends the
single-state threshold-age condition to a two-state (Healthy / Disabled /
Dead) model, using a discretised product-integral over age-varying
Gompertz-type transition intensities.

### Adding a new figure or table

The output layer is designed so this never requires touching path logic:

1. **New figure**: write a `plot_*()` function in `R/04_figures.R` (or a new
   `R/06_*.R` if it belongs to a new analysis), then in `run_analysis.R`:
   ```r
   figS3 <- plot_my_new_check(...)
   save_figure(figS3, "FigS3", "my_new_check",
               caption = "One-line caption for the manifest.",
               width = 8, height = 5, supplementary = TRUE)
   ```
2. **New table**: build the data frame in the relevant `R/0N_*.R` script,
   then call `save_table()` the same way. Main-text tables use
   `supplementary = FALSE` (the default); appendix/referee-response tables
   use `supplementary = TRUE`.
3. Re-run `Rscript run_analysis.R`. The new file lands in the right
   `main/`/`supplementary/` folder as both PDF and PNG (figures) or CSV
   (tables), and is automatically added to `output/manifest.md`.

This follows the standard "research compendium" layout for reproducible
academic code (Marwick, Boettiger & Mullen 2018, *The American Statistician*):
a single entry-point script, source code separated by function, generated
outputs kept out of the analysis code, and dependencies declared explicitly
rather than assumed.

## Reproducing the results

```r
# From the repository root, in R:
install.packages(c("expm", "ggplot2", "dplyr", "tidyr", "tibble",
                    "purrr", "readr", "patchwork", "scales"))
source("run_analysis.R")
```

or from the shell:

```bash
Rscript run_analysis.R
```

This regenerates all four figures (`output/figures/`) and all tables,
including the sensitivity summaries and a `session_info.txt` capture of the
exact package versions used (`output/tables/`).

## Model summary

- **States.** Healthy (1), Disabled (2), Dead (absorbing).
- **Intensities.** Four age-varying Gompertz-type hazards: disability
  incidence (mu12), recovery (mu21), and cause-specific mortality (mu1d,
  mu2d) are combined into a 2x2 generator matrix `A(x)` (`R/01_model.R`,
  `transition_generator()`).
- **Transition probabilities.** The generator is exponentiated on a fine
  age grid (`AGE_STEP = 0.25` years by default; see `config.R`) to build the
  discretised product-integral `P(50, x)` (`build_transition_matrices()`),
  following standard multistate life table methodology (Andersen et al.
  1993; Schoen 1988).
- **Calibration.** Mortality parameters are calibrated so that healthy-start
  life expectancy at age 50 approximates the 2019 US period life table
  (Arias & Xu 2022, CDC/NCHS); disability-transition parameters follow the
  Health and Retirement Study literature (Lievre, Brouard & Heathcote 2003;
  Crimmins, Zhang & Saito 2016). See `config.R` and
  `R/05_calibration_check.R`.
- **Threshold age a\*.** For each initial health composition pi0, `a*`
  solves eq. (30) of the manuscript,
  `bar{H}^ms(a) = 1 + H_ms + ln S^ms(a)`, where `bar{H}^ms(a)` is the
  age-conditional lifespan entropy and `H_ms` the overall (Keyfitz-type)
  multistate entropy. See `compute_lifespan_measures()` in `R/01_model.R`.

## Sensitivity analysis

`R/03_sensitivity.R` reports two checks reproduced in Figure 4:

1. **One-at-a-time (OAT).** Each of the four intensity scale parameters
   (a12, a21, a1d, a2d) is varied ±25% and ±50% around its calibrated
   value, holding the others fixed.
2. **Mortality ratio.** The disabled/healthy excess-mortality ratio
   `r = a2d / a1d` is varied over [1.5, 4.0] with `a1d` held fixed at its
   calibrated value, bracketing the empirical range reported in Rogers,
   Rogers & Belanger (1990), Maddox et al. (1994), and Cai, Hayward &
   Saito (2006).

## Session info

The exact package versions used to generate the results reported in the
manuscript are captured in `output/tables/session_info.txt` after running
`run_analysis.R`. For long-term reproducibility, consider pinning
dependencies with [`renv`](https://rstudio.github.io/renv/) (`renv::init()`

Zenodo, which is recommended for a citable DOI at time of journal
submission).
